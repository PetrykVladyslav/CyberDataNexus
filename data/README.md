## 📌 Про проєкт

**CYBER DATA NEXUS** — веб-застосунок для централізованого управління файлами, який поєднує **хмарне об'єктне зберігання** з **інтелектуальною автоматичною класифікацією та тегуванням** документів на основі NLP-моделей.

Обсяг цифрових даних у світі зростає експоненціально — за прогнозами IDC та Statista, до 2028 року глобальний обсяг створюваної інформації сягне близько **394 зетабайт**. У цих умовах ручне сортування файлів (створення папок, розставляння тегів) стає неефективним і забирає значну частину робочого часу користувача.

Система вирішує цю проблему автоматично: після завантаження файл проходить семантичний аналіз, отримує категорію, підкатегорію та набір тегів **без участі користувача**, а фізичне зберігання даних винесено у масштабоване S3-сумісне хмарне сховище.

### Ключова ідея

> Замість того, щоб користувач вручну організовував файли, система **сама аналізує зміст назви документа**, визначає його тематичну належність та вибудовує логічну структуру зберігання — поєднуючи надійність хмарної інфраструктури з інтелектом NLP-моделей.

### Наукова новизна

Реалізовано комбінований підхід до автоматичної класифікації файлів, що поєднує:
- аналіз розширення файлу (детермінований сигнал найвищого пріоритету);
- семантичні векторні представлення назви файлу (`sentence-transformers/all-MiniLM-L6-v2`);
- трирівневу систему пріоритетів вирішення конфліктів між сигналами.

Такий підхід підвищує точність визначення категорій і тегів для неструктурованих даних порівняно з класичними статистичними методами (TF-IDF, Bag-of-Words).

## ✅ Функціональні можливості

Реалізовано ролеорієнтовану модель доступу **RBAC** з трьома ієрархічними ролями: **Viewer → Editor → Admin** (кожна наступна роль успадковує можливості попередньої).

| Роль | Можливості |
|---|---|
| **Viewer** | реєстрація/автентифікація, перегляд профілю, перегляд і фільтрація файлів, попередній перегляд документів, керування сповіщеннями |
| **Editor** | + завантаження та видалення файлів, ручне редагування тегів/категорій, масові (bulk) операції, перегляд аналітичної панелі |
| **Admin** | + управління користувачами та ролями, перегляд журналу аудиту |

**Основні функції системи:**
- 📤 Завантаження файлів довільних форматів з автоматичною реєстрацією метаданих
- 🤖 Автоматичний семантичний аналіз змісту та генерація тегів
- 🗂️ Автоматичне формування ієрархічної структури категорій/підкатегорій
- 🔍 Семантичний пошук та фільтрація за назвою, тегами, категорією
- ✏️ Ручне редагування тегів і категорій зі стабілізацією ручних правок
- 📊 Аналітична панель (10 показників, 8 інтерактивних графіків на Canvas API)
- 🔔 Smart Alerts — автоматичне виявлення дублікатів, відсутніх тегів, помилок класифікації
- 🔗 Публічні посилання на файли (токенізований доступ)
- 🗑️ М'яке видалення файлів (soft-delete) зі збереженням історії для аудиту
- 📜 Повний журнал аудиту всіх дій користувачів

## 🏗️ Проєктування системи (UML)

> Проєктування виконано у Розділі 2 роботи: сформовано функціональні й нефункціональні вимоги, побудовано повний комплект UML-діаграм та спроєктовано структуру бази даних, нормалізовану до 3НФ.

### Аналіз вимог

Визначено **12 функціональних вимог** (FR1–FR12: реєстрація, автентифікація, завантаження, авто-класифікація, авто-тегування, побудова структури каталогів, пошук, ручне редагування тегів тощо) та **11 нефункціональних вимог** (NFR1–NFR11: час відповіді ≤ 2 с, обробка файлу ≤ 10 с, ≥ 50 одночасних користувачів, доступність 99%, bcrypt-хешування паролів, портативність на Ubuntu 20.04+ тощо).

### Діаграма варіантів використання (Use Case)

Модель включає три ролі користувачів (Viewer/Editor/Admin) та трьох зовнішніх акторів: **AI System** (модуль класифікації), **Cloud Storage** (Backblaze B2), **PostgreSQL DB**.

> 🖼️ *Місце для зображення:* `Рисунок 2.2.1.1 – Діаграма варіантів використання програмної системи`
>
> `![Use Case Diagram](./assets/diagrams/use-case-diagram.png)`

### Діаграми послідовності

Побудовано три ключові діаграми послідовності, що охоплюють 6 основних сценаріїв роботи системи:

**1. Автентифікація та завантаження файлу** — bcrypt-перевірка пароля → видача JWT → проходження файлу через AI-класифікатор → збереження в Backblaze B2 → запис метаданих у PostgreSQL.

> 🖼️ `![Sequence — Auth & Upload](./assets/diagrams/sequence-auth-upload.png)`

**2. Пошук, фільтрація та скачування через Presigned URL** — миттєвий пошук по in-memory кешу з рейтингуванням результатів; завантаження файлу напряму з хмари, минаючи сервер.

> 🖼️ `![Sequence — Search & Download](./assets/diagrams/sequence-search-download.png)`

**3. Аналітика, Smart Alerts та видалення файлу** — агрегаційні запити для дашборду, автоматичне виявлення аномалій, м'яке видалення з міткою для аудиту.

> 🖼️ `![API Testing — Search](./assets/screenshots/postman-search.png)`

**База даних:** керована PostgreSQL-платформа **Supabase**, доступ через SQLAlchemy ORM. Вісім моделей, складені індекси (`ix_files_category_status`, `ix_files_user_status`), UUID як первинний ключ файлів.

### Хмарне зберігання (Backblaze B2)

Порівняно чотирьох провайдерів (AWS S3, Google Cloud Storage, Azure Blob, Backblaze B2) за вартістю зберігання, вихідного трафіку, S3-сумісністю. Обрано **Backblaze B2**: найнижча вартість (≈0,005–0,0069 USD/ГБ/міс проти ≈0,023 USD у AWS S3), повна S3-сумісність через `boto3`, підтримка Presigned URL.

Ключова архітектурна особливість — **пряме завантаження файлів з клієнта в хмару через Presigned URL**, що повністю розвантажує сервер прикладної логіки. Посилання діють 1 годину та підписані алгоритмом AWS Signature v4.

Клас `R2Storage` інкапсулює операції: `build_key`, `upload`, `download`, `delete`, `exists`, `get_presigned_url`, `copy`.

> 🖼️ `![B2 Bucket Contents](./assets/screenshots/b2-bucket-contents.png)`
> 🖼️ *Місце для зображення:* `Рисунок 3.4.2.1 – Блок-схема алгоритму завантаження файлу`
>
> `![Upload Flow Chart](./assets/diagrams/upload-flowchart.png)`

Реалізовано soft-delete, масові операції (bulk tag/move/delete) та повний журнал подій (`file.upload`, `file.delete`, `file.download`, `file.tag_add`, `file.tag_remove`, `file.move`, `storage.migrate`).

> 🖼️ `![Bulk Tagging Flow](./assets/screenshots/bulk-tagging.png)`

### 🤖 Модуль автоматичної класифікації та тегування

Найважливіший інтелектуальний компонент системи — семантичний класифікатор файлів.

**Модель:** `sentence-transformers/all-MiniLM-L6-v2` — 6-шаровий трансформер, 384-вимірний простір ембедингів, 22,7 млн параметрів, попередньо натренований за методологією SimCSE.

**Конвеєр:**
1. Транслітерація кирилиці та нормалізація Unicode
2. Кодування назви файлу в семантичний вектор (frozen encoder, feature extraction, без fine-tuning)
3. Класифікація категорії — `LogisticRegression` (single-label)
4. Класифікація тегів — `OneVsRestClassifier` (multi-label, поріг ймовірності p ≥ 0,4)
5. **Трирівнева система пріоритетів**: розширення файлу → таблиця відповідностей тегів → результат AI-моделі

**Синтетичний датасет:** 100 000 зразків (JSONL), 90% train / 10% val, генерація на основі стохастичної комбінаторики токенів із тематичних пулів (EN/UK), з навмисним шумом (10% видалення тегу, 5% додавання нерелевантного тегу) для підвищення стійкості моделі.

> 🖼️ *Місце для зображення:* `Рисунок 3.5.1.1 – Вихідний датасет`
>
> `![Generated Dataset](./assets/screenshots/dataset-sample.png)`

**Гіперпараметри** підібрано через `GridSearchCV` (3-fold CV): класифікатор категорій — C = 1,0 (lbfgs); класифікатор тегів — C = 3,0.

**Метрики якості на валідаційній вибірці:**

| Класифікатор | Метрика | Значення |
|---|---|---|
| Категорії | Accuracy | **91,39%** |
| Категорії | Macro F1 | **0,921** |
| Теги | Micro F1 | **0,781** |
| Теги | Macro F1 | **0,651** |
| Теги | Hamming Loss | **0,032** |

> 🖼️ *Місце для зображення:* `Рисунок 3.5.2.1 – Метрики оцінки якості навчання моделей`
>
> `![Model Metrics](./assets/screenshots/model-metrics.png)`

Результат: 4 самодостатні артефакти інференсу (`encoder/`, `category_model.pkl`, `tag_model.pkl`, `tag_binarizer.pkl`), що завантажуються один раз при старті Flask-застосунку.
